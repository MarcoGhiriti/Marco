The user wants to build a premium mobile application for motorcyclists called **Moto GO**.

**Initial Product Requirements were extensive (see previous summary). The user provided a new, detailed PRD mid-session which now defines the upcoming work:**

**NEW PRODUCT REQUIREMENTS (PRD):**

-   **🔔 NOTIFICATIONS HUB:**
    -   Friend requests MUST appear in a centralized Notifications hub (accessible from the Home screen icon), NOT in the chat/community section.
    -   This hub should be the central place for all alerts: friend requests, route/event/group invitations, and automated reminders (e.g., Event starts in 1h).

-   **👥 GROUPS (Control & Clarity):**
    -   When creating a group, the creator MUST be able to set a maximum number of members.
    -   In the group chat, every message bubble MUST display the sender's username.

-   **🧑 PROFILE (Content Management):**
    -   In the user's own profile, they MUST be able to **✏️ Edit** and **🗑️ Delete** the routes and events they have created. The profile should be a content management hub.

-   **🛑 RIDES – ADVANCED FUNCTIONS:**
    -   During an active ride session, there MUST be a **PAUSE** button that allows the user to temporarily stop and later resume the ride. Kilometer tracking should only happen when the ride is active (not paused).

-   **🗺️ MINI-MAP UX:**
    -   The mini-map preview on Home/Route cards must be an intelligent zoom-out (like a GPS preview).
    -   It must display the main route polyline highlighted, adjacent streets in gray, and text labels for the **start and end city names** directly on the map.
    -   It must be purely visual, with no raw coordinates shown to the user.

-   **🎯 CORE UX GOALS:**
    -   The app must feel intuitive and map-oriented.
    -   Key actions should take a maximum of 1-2 clicks.

-   **🔑 CORE CONSTRAINTS:**
    -   Routes (start to end path) and Events (single location meetup) remain distinct concepts.
    -   All locations must be selected via a search bar (Google Maps-like), not manual coordinate entry.

</original_problem_statement>
